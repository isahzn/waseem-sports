# PHASE 05 — Checkout, COD, orders, tracking (MVP complete here)
## Tasks
1. Checkout form (configurable required fields, D12), shipping options from `shipping_rules` (D1/D5), COD payment method, order summary; guest only.
2. Server action `placeOrder`: zod -> rate limit -> re-price -> shipping fee -> tracking token (random 32 bytes, store sha256+pepper) -> idempotency key (client-generated per checkout attempt, server-verified) -> RPC `place_order` (reserve per `cod.reserve_stock_on`) -> enqueue notification rows -> redirect to confirmation. Map `INSUFFICIENT_STOCK`/`UNAVAILABLE` errors to friendly messages and cart fixes.
3. Confirmation page + `/track` (order number + token). Limited fields, generic not-found, rate-limited.
4. Admin orders: list (filters by status/date/search, new-orders badge), detail (items snapshot, customer, address, payment, timeline), status change with transition validation, stock actions (reserve-on-confirm / release / commit), internal notes, audit.
5. Basic dashboard: new orders, revenue, top products, low stock.
## Acceptance
- Double-click/refresh/replayed submit creates ONE order. Tampered price/shipping/product id is ignored/rejected.
- Last-unit race test through the real UI/API path: one wins.
- Cancel releases stock; ship commits stock; ledger rows exist; totals in old orders unchanged after price edits.
- Guessing order numbers without token reveals nothing.
